# Диаграмма классов и правила изменения заявки

## 1. Диаграмма

```
                ┌──────────────────────────────────────────┐
                │              TrackedEntity               │
                ├──────────────────────────────────────────┤
                │ - __entity_id : str                      │
                │ - __history   : list[dict]               │
                ├──────────────────────────────────────────┤
                │ + entity_id : str            {read-only} │
                │ + history() -> list[dict]    {копия}     │
                │ # _add_record(field, old, new) : None    │
                └────────────────────┬─────────────────────┘
                                     │ наследование
                                     ▼
                ┌──────────────────────────────────────────┐
                │               Enrollment                 │
                ├──────────────────────────────────────────┤
                │ - _student_email   : str                 │
                │ - _course_code     : str                 │
                │ - _duration_hours  : float               │
                │ - _status          : str                 │
                ├──────────────────────────────────────────┤
                │ + enrollment_id : str        {read-only} │
                │ + student_email : str        {read-only} │
                │ + course_code   : str        {read-only} │
                │ + status        : str        {property}  │
                │ + duration_hours: float      {property}  │
                │ + to_dict() -> dict                      │
                ├──────────────────────────────────────────┤
                │ - _check_email / _check_course_code      │
                │ - _check_duration / _check_status        │
                └──────────────────────────────────────────┘
```

## 2. Инкапсуляция

| Что скрыто | Почему |
|---|---|
| `__entity_id` | идентификатор нельзя заменить после создания |
| `__history` | журнал нельзя очистить или подделать снаружи |
| `_student_email`, `_course_code` | меняются только через проверку в конструкторе |
| `_status`, `_duration_hours` | меняются только через property с проверкой |

Снаружи доступны только чтение свойств и `history()`, который возвращает копию
списка и копии каждой записи. Поэтому `copy.clear()` и `copy[0]["new"] = ...`
не затрагивают настоящий журнал.

## 3. Разрешённые переходы статуса

| Текущий статус | Можно перейти в | Смысл |
|---|---|---|
| `new` | `on_review`, `cancelled` | новая заявка уходит на проверку или отменяется |
| `on_review` | `enrolled`, `cancelled` | проверка закончена: зачислен или отказ |
| `enrolled` | `completed`, `cancelled` | обучение завершено или прервано |
| `completed` | — | терминальный статус |
| `cancelled` | — | терминальный статус |

```
new ──► on_review ──► enrolled ──► completed
 │          │            │
 └──────────┴────────────┴──────► cancelled
```

Правила:

* неизвестный статус — `ValueError`;
* переход, которого нет в таблице, — `ValueError` с перечнем разрешённых;
* повторная установка того же статуса ничего не делает и в журнал не пишется.

## 4. Формат записи журнала

```python
{
    "at": "2026-11-23T12:00:00",   # время изменения
    "field": "status",             # что изменили
    "old": "on_review",            # было
    "new": "enrolled"              # стало
}
```

Одна и та же структура используется и для `status`, и для `duration_hours`:
`field` отличает изменения, поэтому история остаётся единообразной.

## 5. Связь с базой данных

Класс `Enrollment` повторяет бизнес-правила таблицы `enrollments`:

* e-mail проверяется тем же регулярным выражением `validators.EMAIL_RE`;
* код курса — `validators.COURSE_CODE_RE`;
* длительность — диапазон `MIN_DURATION..MAX_DURATION`;
* статусы — белый список `validators.VALID_STATUSES`.

При этом класс не обращается к SQLite: он проверяет объект до записи в базу,
а база дополнительно защищает данные ограничениями `CHECK`/`FOREIGN KEY`.
