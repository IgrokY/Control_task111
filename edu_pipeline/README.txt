ПРОЕКТ edu_pipeline
Итоговая контрольная работа: платформа обучения «НОРД-Класс»
========================================================================

1. НАЗНАЧЕНИЕ
------------------------------------------------------------------------
Проект проходит полный путь обработки заявок на обучение:

    сырой CSV -> валидация -> база SQLite -> аналитический отчёт
              -> выгрузка JSON/XML -> тесты, отладка, кодировки

Исходные файлы из data/final/ НЕ ИЗМЕНЯЮТСЯ. Все результаты пишутся
в папку edu_pipeline.

2. ТРЕБОВАНИЯ
------------------------------------------------------------------------
* Python 3.10 или новее (проверено на 3.10.11).
* Сторонние библиотеки не нужны: только стандартная библиотека
  (csv, sqlite3, json, xml.etree.ElementTree, re, collections, timeit,
  unittest, unicodedata).
* Jupyter нужен только для просмотра ноутбука report_enrollments.ipynb.

3. БЫСТРЫЙ ЗАПУСК
------------------------------------------------------------------------
Из папки edu_pipeline:

    python run_all.py

Скрипт последовательно выполнит Этапы 2–7, прогонит все тесты и сверит
контрольные суммы файлов data/final/ до и после запуска.

Отдельно ноутбук:

    открыть report_enrollments.ipynb -> Kernel -> Restart & Run All

4. ПОШАГОВЫЙ ЗАПУСК (если нужен контроль каждого этапа)
------------------------------------------------------------------------
    python normalize_audit.py     # Этап 3: журнал -> before_after.csv
    python review_queue.py        # Этап 2: две реализации очереди
    python create_db.py           # Этап 4: схема edu.db + справочники
    python etl_import.py          # Этап 5: заявки -> edu.db
    python queries.py             # Этап 4: выборки и агрегаты
    python batch_load.py          # Этап 4: commit/rollback, протокол
    python export_data.py         # Этап 5: report.json, report.xml
    python demo.py                # Этап 6: класс Enrollment
    python performance_bench.py   # Этап 7: замеры timeit
    python unicode_diagnostics.py # Этап 7: CP1251/UTF-8
    python -m unittest discover -v  # Этап 7: все тесты

Порядок важен: create_db.py пересоздаёт edu.db, поэтому etl_import.py
запускается после него. Скрипты можно запускать повторно: ETL не создаёт
дублей, а транзакционные опыты откатываются.

7. ЧИСТЫЙ ПЕРЕЗАПУСК
------------------------------------------------------------------------
Удалить сгенерированные файлы можно вручную или просто выполнить:

    python create_db.py

Она пересоздаст edu.db. Остальные отчёты (CSV, TXT, JSON, XML) при запуске
перезаписываются. Скрипт run_all.py не требует ручной очистки: он всегда
начинает с normalize_audit.py и create_db.py.

8. ОСОБЕННОСТИ ДАННЫХ
------------------------------------------------------------------------
* В строке 18 файла enrollments_raw.csv e-mail содержит неэкранированную
  запятую. csv.DictReader складывает лишнее поле в ключ None; ETL видит это
  и отклоняет строку с причиной malformed_row, не пытаясь «угадать» поля.
* Строка EDU-202610-0006 встречается дважды: первая принимается, вторая
  отклоняется как duplicate_enrollment_id.
* audit_messy.log содержит лишние пробелы, двойные разделители, разные
  кавычки; нормализация не удаляет информацию, а приводит оформление к
  единому виду. Незакрытые кавычки остаются как есть.
* names_cp1251.txt (122 байта, без BOM) и names_utf8.txt (232 байта, с BOM)
  содержат один и тот же список имён. Диагностика подтверждает: CP1251
  декодируется в текст, совпадающий с UTF-8-эталоном.

9. КОДИРОВКИ
------------------------------------------------------------------------
Кодировка указывается явно при каждом чтении и записи:

* CSV для Excel — utf-8-sig (BOM помогает Excel);
* JSON/XML/Markdown/TXT — utf-8;
* CP1251 — только для names_cp1251.txt, где он действительно используется;
* errors="ignore" нигде не применяется: ошибка декодирования должна быть видна.

10. ТЕСТЫ

    python -m unittest discover -v

Ожидаемый результат: 62 теста, OK. Тесты не изменяют рабочие файлы:
используются временные каталоги и базы :memory:.
